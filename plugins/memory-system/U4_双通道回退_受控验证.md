## A2. 受控且可逆地制造 HTTP 失败（改法 + 恢复步骤；**先落盘后执行**）

**做法（路由面封锁，非代码改动）**：用**动态 Cordis Host 探针**（`cordis_define` + `cordis_run`）注册 3 条 **exact** 路由：

| 遮蔽路径 | 行为 |
|---|---|
| `/knowledge-base/api/search` | 收请求 → 记录 body → **503** `{"ok":false,"error":"t107-controlled-block"}` |
| `/skill-center/api/route` | 同上 |
| `/t107block/report` | 返回探针状态（含被命中的请求记录），仅供自证 |

- **为何生效**：宿主 webServer 路由表 **exact 表先于 prefixes 表**（`dsh-host-webserver/lib/index.js` L323-326：`const exact = this.exact.get(pathname); if (exact !== undefined) return exact;`），而 knowledge-base / skill-center 自身注册的是 **prefixes**（`kind:'prefixes'`）⇒ 探针 exact 路由优先命中。
- **为何等价于「HTTP 不可达」**：`httpJson` 对 `!res.ok` 直接 `return null`（**L379**）⇒ 与连接失败/不可达端口在**调用方语义上等价**，必然走回退分支。
- **为何不改 apiBase**：`apiBase()` 读**宿主进程** env（L361-365），不重启无法改变 ⇒ 违背 A5，故不采用。
- **恢复步骤（先落盘）**：`cordis_stop(tblk-1)` → `cordis_undefine(tblk-1)` → 校验两端点恢复原响应 + 探针路由 404。本任务**已按此执行完毕**（见 §A4）。
- **影响面**：仅窗口内、仅这 2 个 endpoint；邻接路径实测未受影响（`/knowledge-base/api/list` 200/1145 条、`/skill-center/api/list` 200/6 条、`/memory-system/api/ping` 200）。
- 探针时刻：`registeredAt=2026-09-19T11:37:30.677Z`；封锁窗口 `11:37:42.545Z`；恢复窗口 `11:38:52.062Z`。

  - 代码级证据：pre-O5 快照（`_backup/memory-system-pre-o5-20260919-180719/lib/index.js`）与当前版本逐函数对比 —— **`scoreEntry`（old L321 / new L337）、`scoreAndSort`（old L334 / new L350）、`httpJson`（old L350 / new L366）三段完全一致**；`kbSearch`/`skillRoute` 的差异**仅一处**：`readJson(` → `readJsonRef(`（即只换了 fs 访问器），HTTP 分支判定条件、`channel` 语义、评分与回退逻辑**逐行相同**。
